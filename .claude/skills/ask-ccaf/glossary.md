# Glossary — Claude Certified Architect: Foundations (CCAR-F)

**`--json-schema`** — Claude Code CLI flag enforcing a structured output schema, paired with `--output-format json` for CI (Ch 4, Ch 10)
**`--output-format json`** — Claude Code CLI flag producing machine-parseable output for automated PR comments (Ch 4)
**`--print` / `-p`** — Claude Code flag for non-interactive mode; required in CI to prevent input hangs (Ch 4, Ch 8)
**`--resume <session-name>`** — resumes a specific named prior conversation (Ch 2)
**`.claude/commands/`** — project-scoped slash commands, shared via version control (Ch 4, Ch 8)
**`.claude/rules/`** — directory of topic-specific rule files; YAML frontmatter `paths:` globs activate them conditionally (Ch 4, Ch 8)
**`.claude/skills/`** — project-scoped skills, each a `SKILL.md` with frontmatter (Ch 4)
**`.mcp.json`** — project-scoped MCP server configuration, shared via version control; supports `${VAR}` expansion (Ch 3)
**`~/.claude.json`** — user-scoped MCP server configuration for personal or experimental servers (Ch 3)
**Access failure** — a tool call that could not complete (e.g. timeout), requiring a retry decision; distinct from a valid empty result (Ch 3, Ch 6)
**Agentic loop** — send request → inspect `stop_reason` → execute tools → return results, repeating until `"end_turn"` (Ch 2)
**AgentDefinition** — Agent SDK configuration of a subagent's description, system prompt, and tool restrictions (Ch 2)
**`allowed-tools`** — SKILL.md frontmatter restricting tool access during skill execution (Ch 4)
**`allowedTools`** — Agent SDK setting listing an agent's permitted tools; must include `"Task"` to spawn subagents (Ch 2)
**`argument-hint`** — SKILL.md frontmatter prompting for required parameters on bare invocation (Ch 4)
**Attention dilution** — degraded, uneven analysis when too much material is processed in one pass (Ch 2, Ch 5, Ch 8)
**Case facts block** — extracted transactional facts (amounts, dates, IDs) injected into each prompt outside summarized history (Ch 6)
**CCAR-F** — the exam code for Claude Certified Architect – Foundations (Ch 1)
**CLAUDE.md hierarchy** — user (`~/.claude/CLAUDE.md`), project (`.claude/CLAUDE.md` or root), and directory-level memory files (Ch 4)
**Claim-source mapping** — structured pairing of a claim with its source URL, document name, and excerpt, preserved through synthesis (Ch 6)
**`/compact`** — Claude Code command reducing context usage during long sessions (Ch 6)
**Confidence calibration** — tuning field-level confidence thresholds against labeled validation sets (Ch 6)
**Context degradation** — in extended sessions, drifting toward "typical patterns" instead of specifics discovered earlier (Ch 6)
**`context: fork`** — SKILL.md frontmatter running a skill in an isolated sub-agent context (Ch 4, Ch 8)
**Coordinator-subagent pattern** — hub-and-spoke architecture where a coordinator routes all subagent communication (Ch 2)
**Coverage annotation** — marking which synthesis findings are well-supported and which topics have gaps (Ch 6)
**Criterion-referenced** — scored against a fixed standard, not against other candidates (Ch 8)
**`custom_id`** — Message Batches API field correlating request and response pairs (Ch 5)
**Cut score** — 720 on the 100–1,000 scaled range (Ch 1, Ch 8)
**`detected_pattern`** — a field added to findings so dismissal patterns can be analyzed (Ch 5)
**Direct execution** — working without plan mode; appropriate for simple, well-scoped changes (Ch 4)
**Explore subagent** — Claude Code subagent isolating verbose discovery and returning summaries (Ch 4)
**Few-shot examples** — 2–4 targeted examples showing reasoning and format for ambiguous cases (Ch 5)
**`fork_session`** — creates an independent branch from a shared analysis baseline (Ch 2)
**Hub-and-spoke** — see coordinator-subagent pattern (Ch 2)
**`@import`** — CLAUDE.md syntax referencing external files to keep configuration modular (Ch 4)
**`isError`** — MCP flag communicating tool failure back to the agent (Ch 3)
**`isRetryable`** — structured error field telling the agent whether retrying can succeed (Ch 3)
**Iterative refinement loop** — coordinator evaluates synthesis for gaps, re-delegates, re-synthesizes (Ch 2)
**Interview pattern** — having Claude ask clarifying questions before implementing (Ch 4)
**Job task analysis** — the study that set the blueprint's domain weights (Ch 1)
**Lost in the middle** — reliable processing at the start and end of long inputs, omissions in the middle (Ch 6)
**Manifest** — the state export a coordinator loads on resume for crash recovery (Ch 6)
**MCP resource** — a content catalog exposed to agents to reduce exploratory tool calls (Ch 3)
**Message Batches API** — 50% cost savings, up to 24-hour window, no latency SLA, no multi-turn tool calling (Ch 5)
**`/memory`** — Claude Code command showing which memory files are loaded (Ch 4)
**Minimally qualified candidate** — the performance level the standard-setting study used to set the cut score (Ch 8)
**Model-driven decision-making** — Claude choosing the next tool from context, versus a pre-configured decision tree (Ch 2)
**Multi-pass review** — per-file local passes plus a separate cross-file integration pass (Ch 5)
**Plan mode** — Claude Code mode for exploration and design before large-scale or architectural changes (Ch 4)
**PostToolUse hook** — intercepts tool results for transformation before the model processes them (Ch 2)
**Programmatic enforcement** — hooks and prerequisite gates giving deterministic guarantees, unlike prompts (Ch 2)
**Progressive summarization** — compressing history, at the risk of losing numbers, dates, and stated expectations (Ch 6)
**Prompt chaining** — fixed sequential decomposition into focused passes (Ch 2, Ch 5)
**Retry-with-error-feedback** — resending the document, the failed extraction, and the specific validation errors (Ch 5)
**Scaled score** — 100–1,000 reporting range that equates difficulty across exam forms (Ch 8)
**Scoped tool access** — giving each agent only role-relevant tools, plus limited cross-role tools (Ch 3)
**Scratchpad file** — a file persisting key findings across context boundaries (Ch 6)
**Self-review limitation** — a model retains generation reasoning and under-questions its own output in-session (Ch 5)
**Semantic validation error** — values that parse but are wrong (totals that don't sum, misplaced fields) (Ch 5)
**Session context isolation** — an independent instance reviews better than the session that generated the code (Ch 4, Ch 5)
**Standard-setting study** — the SME process that established the passing score (Ch 8)
**`stop_reason`** — API field driving loop control; `"tool_use"` continues, `"end_turn"` terminates (Ch 2)
**Stratified random sampling** — sampling high-confidence extractions to measure error rates and find novel failures (Ch 6)
**Structured error context** — failure type, attempted query, partial results, and alternatives, sent to the coordinator (Ch 6)
**Structured handoff** — escalation payload (customer ID, root cause, amount, recommended action) for a human without transcript access (Ch 2)
**Task statement** — a tested objective with "Knowledge of" and "Skills in" bullets; exam items are written against these (Ch 1)
**Task tool** — the mechanism for spawning subagents (Ch 2)
**`tool_choice`** — `"auto"` (may return text), `"any"` (must call some tool), or forced `{"type":"tool","name":"..."}` (Ch 3, Ch 5)
**`tool_use`** — API mechanism that, with a JSON schema, guarantees schema-compliant structured output (Ch 5)
**Transient / validation / business / permission errors** — the four error categories MCP tools should distinguish (Ch 3)
**Valid empty result** — a successful query returning no matches; must not be reported as a failure (Ch 3, Ch 6)

# Supplementary terms — Partner Academy prep courses

*Corpus-derived; not from the Exam Guide. Guide terms above take precedence for exam answers. Product-surface entries move fast; verify current docs.*

**acceptEdits** — permission mode auto-approving reads, file edits, and common filesystem commands inside the working directory; other shell commands still prompt (ch04)
**Agent (vs workflow)** — task + abstract tools, Claude plans the steps; flexible but lower completion rate and harder to eval (ch02)
**auto mode** — permission mode (preview) running everything while a separate classifier reviews each action's intent; never judges correctness (ch04)
**bypassPermissions** — skips all permission checks including the protected-path guard; only inside disposable containers/VMs (ch04)
**Chaining workflow** — fixed sequence of focused calls; a rewrite pass enforces constraints a single pass keeps violating (ch02)
**Classifier (permission)** — the model reviewing each auto-mode action; blocks intent escalation (deploys, force-push, exfiltration, mass deletes) (ch04)
**CLAUDE.local.md / local memory** — personal, per-project memory layer; loads alongside managed policy, user, and project memory (ch04)
**Code grader** — programmatic eval check (JSON parse, AST compile, regex compile) scoring 10-or-0; catches form, not content (ch05)
**Direct resource** — MCP resource with a static URI (`docs://documents`) (ch03)
**dontAsk** — permission mode allowing only pre-approved tools; everything else auto-denied with no prompt — CI and unattended pipelines (ch04)
**Evaluator-optimizer** — producer → grader loop with feedback until the output meets criteria (ch02)
**Exit code 2** — the blocking hook exit code; stderr is fed back to Claude. Exit 1 does **not** block (ch04)
**Explore/Plan subagents (context)** — built-ins that skip CLAUDE.md for speed; the general-purpose subagent loads it (ch04)
**`is_error`** (tool_result) — flag marking a failed tool run; the error text is the model's repair signal for corrected retries (ch03)
**LLM-as-judge / model grader** — a second model scores output against a rubric; demand reasoning before the score and calibrate against human labels (ch05)
**Managed policy / managed-settings.json** — enterprise settings layer administrators control; cannot be overridden, survives bypass mode (ch04)
**Marketplace** — a catalog of plugins; added once per team, installs resolve through it with version tracking (ch04)
**MCP Inspector** — browser debugger (`mcp dev`) for invoking a server's tools, resources, and prompts without a client app (ch03)
**MCP prompt** — user-controlled server primitive: a tested prompt template returned as ready-to-send messages (ch03)
**`mcp__server__tool`** — permission-rule syntax naming one MCP tool; a deny on one tool overrides an allow on the server (ch03, ch04)
**Parallelization workflow** — independent subtask calls run concurrently, merged by an aggregator call (ch02)
**Permission decision (hook)** — PreToolUse JSON verdict: allow / deny / ask (defer exists for `-p` runs only) (ch04)
**Plugin** — one versioned installable unit bundling skills, subagents, hooks, commands, and MCP configs; manifest `.claude-plugin/plugin.json`; components namespaced by plugin name (ch04)
**Prefill + stop sequence** — starting the assistant message and cutting generation at a marker to get raw payload without commentary (ch05)
**PreToolUse** — the hook event that fires before a tool call — the only point that can block or rewrite it (ch04)
**Rewind / checkpoint** — every user prompt creates a checkpoint; double-Escape restores code, conversation, or both (ch04)
**Routine** — (preview) saved prompt + repo + connectors run on Anthropic-managed infrastructure on cron/HTTP/GitHub triggers; fresh default-branch clone, pushes restricted to `claude/` branches (ch04)
**Routing workflow** — classify the input, then forward to a category-specialized prompt or pipeline (ch02)
**SessionStart (compact matcher)** — hook slot that re-injects state right after compaction so the session resumes warm (ch04, ch06)
**stdio / HTTP transport** — MCP transports: local subprocess vs remote/shared server; SSE is legacy (ch03)
**Stop hook** — fires when the model wants to end its turn; exit 2 refuses "done" — the test-gate for unsupervised runs (ch04)
**Templated resource** — MCP resource whose URI carries parameters parsed into function arguments (ch03)
**`tool_use_id`** — the id pairing a tool_result to its tool_use block; pairing is by id, not ordering (ch03)
**`updatedInput`** — PreToolUse return that rewrites a tool call without blocking; replaces the whole input object, so echo unchanged fields (ch04)
**Workflow (vs agent)** — predefined series of Claude calls for a known step sequence; higher completion rate, easier to eval (ch02)
**Worktree** — independent git file tree per session so parallel agents don't fight over files; `.worktreeinclude` copies git-ignored files in (ch04)
